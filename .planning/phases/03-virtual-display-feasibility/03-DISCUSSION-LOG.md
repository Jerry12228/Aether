## 失败与恢复体验

### 1. 四组验证中部分组失败？

| Option | Description | Selected |
|--------|-------------|----------|
| 保留成功组 | 失败组回滚自身本次资源，允许单独重试。 | ✓ |
| 整套验证回滚 | 撤销本次新建的所有组，既有组不受影响。 |  |

**User's choice:** 1 — 保留成功组
**Notes:** 保留成功组；单组操作失败回滚、不误删其他组的既有约束保留。

### 2. 请求规格不支持时？

| Option | Description | Selected |
|--------|-------------|----------|
| 严格按请求验证 | 拒绝该组操作，说明原因及可用规格，保留已有状态。 | ✓ |
| 允许显式降级 | 只有显式允许才采用替代规格，默认严格拒绝。 |  |

**User's choice:** 1 — 严格按请求验证
**Notes:** 严格验证，不自动降级；用户修改请求后重试。

### 3. 驱动故障/重置后怎样恢复？

| Option | Description | Selected |
|--------|-------------|----------|
| 显式恢复命令 | 先报告差异，由用户指定组，按原身份和最后成功配置恢复。 | ✓ |
| 原型验证期间自动恢复 | 故障程序检测并恢复，失败时停止报告。 |  |

**User's choice:** 1 — 显式恢复命令
**Notes:** 采用显式恢复命令。

### 4. 重复创建同名已有组？

| Option | Description | Selected |
|--------|-------------|----------|
| 相同配置视为成功 | 返回已有组；配置不同报错并要求调参。 |  |
| 一律报已存在 | 创建只创建新组，已有组用查询/调参/恢复操作。 | ✓ |

**User's choice:** 2 — 一律报已存在
**Notes:** 一律报已存在，即使相同配置也不视为创建成功。
