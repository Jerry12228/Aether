# 会话与资源模型

状态：设计约束已确认；实现策略待相关阶段验证。实例不是另一 Windows 用户桌面，也不是隔离容器。

## 术语

| 对象 | 生命周期与职责 |
|------|----------------|
| Host | 一台 Windows 主机，持有唯一仲裁与资源登记入口 |
| Instance | 独立应用会话，拥有配置、应用进程关联与虚拟显示器组，具有持久 instance_id |
| Client | 已配对 Selene 身份，拥有可协商设备与显示能力 |
| Connection | 临时认证传输连接，掉线不等于 Instance 停止 |
| ControlLease | 全主机唯一控制租约，绑定 instance_id、client_id、connection_id 和递增 epoch |
| DisplayGroup | 由 Instance 拥有的稳定逻辑显示器组 |
| Stream | 单个显示器的视频流；包含 stream_id、display_id、codec、时间戳与版本 |

推荐一个 Helios 主机协调器 + 每实例工作进程，以限制崩溃影响；不要求多套独立服务。实例不能绕过协调器直接注入输入或创建无登记设备。

## 状态与不变量

Instance 生命周期：`Created → Starting → Running → Stopping → Stopped`，异常进入 `Faulted`。Running 中有 `Uncontrolled` / `Controlled` 属性，连接不是生命周期状态。

- 同时可有多个 Running Instance；Host 的有效 ControlLease 始终至多一个。
- 控制权允许多屏、多流；多个流不等于多个控制租约。
- 切换 A→B：认证 B 权限、准备 B 资源，撤销 A 租约，释放按下的键/手柄状态，提升 epoch，授予 B；准备失败可保留 A，但不能出现双持有。
- 超时或断连：撤销租约、停止对应上行采集和下行传输，保留实例、应用进程关联、配置与显示器组。
- 显式 StopInstance：幂等地停本实例拥有的进程/资源，撤销租约并移除该组显示器；不得停止其他实例或共享服务。
- 普通断连绝不隐式 StopInstance。客户端必须分开提供“断开”与“停止实例”。
- 重连使用同一实例及显示器身份；旧 connection/epoch 的输入、码率修改、设备包与剪切板消息被拒绝。
- 后台实例默认不产生无人消费的视频编码负载；应用与虚拟显示器继续运行。

## 显示器身份与多屏

逻辑标识建议来自 `host_id + instance_id + slot_id`，不以临时连接 ID 分配。客户端请求数量、尺寸、刷新率、缩放、位置、HDR 等；服务端先检查总资源预算，再事务性创建/调整显示器与流。

断连保留最后成功拓扑，避免后台应用迁屏；显式更新拓扑才增删 slot。Windows 重启/注销会终止实际进程和系统显示器，不能承诺跨重启保活；启动时对持久配置与现实设备状态做恢复登记，自动重启应用需另行明确策略。

物理显示器/已有桌面捕获路径仍保留。用户能选择捕获来源，不能只允许虚拟屏。

## 同一桌面的实际边界

显示器分组只分配捕获目标，不能限制应用只能在本组显示，也不能隔离前台焦点、剪切板、系统音频和其他应用。提供启动窗口位置、恢复布局及明确的共享桌面说明；不能宣称独立桌面或音频隔离。

停止进程以明确所有权为依据，遇到外部复用进程必须记录策略。受控实例切换会影响系统全局焦点；Windows 本地用户输入仍可介入。UAC 安全桌面、锁屏、DRM、反作弊等行为按原功能基线单独测试和记录。

## 外设与安全

上行设备仅对当前授权租约启用，客户端可随时关闭或撤销权限。非受控实例不应收到旧客户端实时麦克风/摄像头数据。实例切换时停止旧路由、清空缓冲，避免泄漏。

系统虚拟设备可能被同桌面任意程序打开；租约控制的是媒体来源与 Aether 操作权限，不能承诺 Windows 应用级设备隔离。设备是否持久注册、每实例命名或共享单入口，由 Phase 4/5 的证据确定；与显示器组独立保活要求区分。

首版不引入多个并行只读观察者；若原功能基线发现对应能力，先登记差异并讨论读流授权，仍必须保持主机最多一个被控实例。
